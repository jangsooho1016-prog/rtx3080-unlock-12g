# MSI RTX 3080 SUPRIM X 12G LHR 포트

원본은 MSI RTX 3080 **10GB** 한 장(`10de:2206`, subsystem `1462:3890`, VBIOS `94.02.59.00.aa`)과 한 대의 PC에 모든 검사를 고정해 두었습니다. 이 포트는 대상을 **RTX 3080 12GB(`10de:220a`)**로 바꾸고, 카드·PC마다 달라지는 값은 추측하지 않고 **내 PC에서 읽기 전용 프로브로 측정한 값**으로 채우도록 바꿨습니다.

> 2026-10-19, 아래 PC에서 기본 빌드(SS0만)를 실제로 실행해 성공했습니다. 실행 로그는 [evidence/12g-unlock-run00/REPORT.TXT](../evidence/12g-unlock-run00/REPORT.TXT), 측정 결과는 [README](../README.md#측정-결과)에 있습니다. 같은 날 `-Ss1Full`(SS1=`0x8`) 빌드도 실행해 성공했습니다([로그](../evidence/12g-unlock-ss1-run00/REPORT.TXT)).

## 바뀐 점

| 항목 | 원본 (10GB) | 이 포트 |
| --- | --- | --- |
| PCI ID | `0x220610de` 고정 | `0x220a10de` (`unlock/board_ids.h`) |
| Subsystem | `0x38901462` 고정 | 프로브 측정값 |
| 사용 가능 VRAM 레지스터(`0x1183a4`) | `0x2800` (10240 MiB) | 프로브 측정값 (12G는 `0x3000` 예상) |
| BAR0 주소 | `0x84000000` 고정 | 프로브 측정값 (메인보드가 배정) |
| Cold SS0 / PLM | `0x46254040` / `0xffffff8f` | 프로브 측정값 |
| Cold SS1 | `2` 또는 `3`만 허용 | 프로브 측정값 (8 제외 4비트) |
| SS1 쓰기 | 항상 `0x8` | **기본은 보존(쓰기 없음)**, `-Ss1Full`일 때만 `0x8` |
| PROM(VBIOS) SHA256 | 10GB 카드 해시 | 내 카드의 `PROM.BIN` 해시 |
| 설정 공간 `0xc8`, class/rev, BOOT0 | 고정 | 프로브 측정값 |

측정값은 `unlock/board_measured.h`에 들어가며, 이 파일이 없거나 다른 GPU에서 만든 것이면 **빌드가 실패**합니다. 단위 테스트는 원본 10GB 증거를 재생하므로 `unlock/tests/board_fixture_3080_10g.h`로 따로 돌아갑니다.

## SS1 정책

[GA107 포트](https://github.com/IHaBiS02/ga107-unlock)를 참고해 기본 동작을 **SS0=`0x88888888`만 쓰고 SS1은 그대로 두는** 방식으로 바꿨습니다. 해당 포트의 RTX 3050 Laptop에서는 SS0만으로 FP16/BF16(FP32 누산) 처리량이 늘었고, SS1은 TF32에만 영향을 줬습니다. 그 카드도 cold SS1이 `0x7`이었고, 별도 옵션으로 `0x7→0x8`을 실제로 적용했습니다.

- 기본 빌드: `unlock\build.ps1` → SS1은 쓰지 않고, FLR 전후에 cold 값 그대로인지 확인만 합니다.
- SS1 실험: `unlock\build.ps1 -Ss1Full` → 원본처럼 SS1=`0x8`을 씁니다. 이 PC에서 `0x7→0x8` 적용과 FLR 후 유지를 확인했고, TF32 처리량이 31.17 → 60.37 TFLOPS(8192, 전력 100%)로 늘었습니다.

## 이 PC의 프로브 결과 (2026-10-19)

원본 로그: [evidence/12g-probe-run00/REPORT.TXT](../evidence/12g-probe-run00/REPORT.TXT)

- `01:00.0`, `10de:220a`, subsystem `1462:3897`, MSI VBIOS `94.02.85.00.6F`
- Intel UHD 770 GOP `00:02.0` 1920×1080, BAR0 `0x84000000`/16 MiB, BOOT0 `0xb72000a1`
- cold: GFW 완료, WPR2 꺼짐, PLM `0xffffff8f`, **SS0 `0x40132104`, SS1 `0x7`**, FB `0x3000`(12288 MiB)
- VBIOS의 FWSEC은 원본과 같은 형식(ucode 9, 서명 3개, versions `0x7`)으로 파싱됨. 실제 fuse 버전은 실행 때 읽으며, 맞는 서명이 없으면 펌웨어 실행 전에 중단합니다.

## 사용 순서

1. **프로브 빌드** (읽기 전용, GPU 쓰기·리셋 없음)
   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\build-probe.ps1
   ```
2. FAT32 USB에 `probe\build\BOOTX64.EFI` → `USB:\EFI\BOOT\BOOTX64.EFI`, 빈 폴더 `USB:\RTX3080-PROBE`를 만듭니다.
3. 모니터를 **메인보드(Intel 내장그래픽)** 에 연결하고 Secure Boot를 끈 뒤, PC를 **완전히 끈 상태에서** 켜서 USB로 부팅합니다.
4. `USB:\RTX3080-PROBE\RUN00\`에 생긴 `REPORT.TXT`, `PROM.BIN`으로 프로필을 만듭니다.
   ```powershell
   python .\tools\make_board_profile.py --report E:\RTX3080-PROBE\RUN00\REPORT.TXT --prom E:\RTX3080-PROBE\RUN00\PROM.BIN --output .\unlock\board_measured.h
   ```
   `ERROR`가 나오면 그 카드/PC 상태로는 진행하지 않습니다. `WARNING`은 원본과 다른 값이라는 뜻이고, 특히 **SS0 값이 다르면** 원본에서 검증된 경로가 아니라는 뜻입니다.
5. 실행 자산 5개를 만듭니다 (아래).
6. `unlock\build.ps1` → `python tools\package_usb.py --assets <자산 폴더> --output <새 폴더>` → [docs/USB-BOOT.md](USB-BOOT.md).

## 실행 자산 5개

원본 저장소에는 자산 생성 도구가 없습니다. 이 PC의 실행에는 [IHaBiS02/ga107-unlock](https://github.com/IHaBiS02/ga107-unlock)의 `firmware/` 스크립트로 만든 파일을 썼습니다(Python 3.13, `zstd` 필요).

```bash
git clone https://github.com/IHaBiS02/ga107-unlock && cd ga107-unlock
python firmware/fetch_artifacts.py ../inputs          # NVIDIA 소스 + CachyOS nvidia-utils 610.43.03, SHA-256 검증
tar -xJf ../inputs/NVIDIA-kernel-module-source-610.43.03.tar.xz -C ../src
python firmware/generate_v67.py ../inputs/nvidia-utils-610.43.03-1-x86_64_v3.pkg.tar.zst ../assets
python firmware/extract_boot_assets.py ../src/NVIDIA-kernel-module-source-610.43.03 ../assets
```

만든 5개 파일은 이름·크기·SHA256이 `unlock/assets.json`과 모두 일치해야 하며, 이 PC에서 사용한 파일은 일치했습니다. NVIDIA 펌웨어는 재배포하지 않으므로 저장소에 포함하지 않습니다.

## 이 포트로도 안 되는 조건

- **Intel 내장그래픽 화면 출력이 필수**입니다. F 모델 Intel CPU나 내장그래픽 없는 Ryzen이면 화면 검사에서 거부됩니다.
- GPU가 `0000:01:00.0`(첫 번째 x16 슬롯)에 있어야 합니다.
- 실행 자산 5개(`unlock/assets.json`)와 Windows 드라이버 버전은 610.x 계열을 전제로 합니다. 이 PC는 610.88에서 확인했습니다.

## 위험

- 코드상 VBIOS 플래시에 쓰지 않고, 효과는 전원을 완전히 끄면 사라지는 것으로 설계되어 있습니다. 그래도 GPU 보안 펌웨어(FWSEC/Booter)를 직접 구동하고 기능 선택 레지스터를 바꾸는 실험이므로, 실패 시 멈춤·드라이버 오류가 날 수 있습니다. `STOP / POWER OFF`가 나오면 전원 버튼으로 끄세요.
- 이 PC의 카드는 FWSEC fuse 버전 2, Booter fuse 버전 1로 원본과 같았습니다. 다른 12G 카드는 VBIOS·퓨즈 버전이 다를 수 있습니다.
- 장시간 안정성과 계산 정확도는 아직 따로 검증하지 않았습니다.
